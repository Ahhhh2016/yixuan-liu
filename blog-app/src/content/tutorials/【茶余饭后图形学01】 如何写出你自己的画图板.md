# 什么是图片？
回想一下生物课上学的眼睛如何看到东西，或者也许有朋友知道相机的成像原理：光进入镜头或眼睛被转变成信号。信号可以是连续的，但现实世界中的图片不行（这让我联想到游戏Minecraft，世界被离散成一个个方块）。像素（pixel）已经是我们非常熟悉的一个概念了，但大家可能不知道，pixel stands for picture element。我们通过对信号的采样（sampling），把连续的信号变成离散的一个个像素点，就组成了图片。

大家很容易想到，在计算机的世界中，我们可以用数字来表示像素点。可以就拿c++来当栗子好了，数据类型有int, long long, float, double等等，应该用哪一种呢？
答案是都可以，按需取用（笑）。

我们先从简单的黑白图片（grayscale images）开始。如果我们只用0和1来代表白色和黑色，就只能得到非黑即白的图片，但如果我们能用8 bits的integer，就可以有256种不同的黑白灰！
![](</images/graphics-tutorials/茶余饭后图形学01 如何写出你自己的画图软件.webp>)
（图1. 来源：课程PPT by Prof. James Tompkin, Brown University, 
CSCI 1430: Computer Vision, Spring 2026）

因为我们想得到漂亮一些的结果，就用我们要用256level的8 bits数字来表示像素，也就是1个像素在计算机世界中是一个[0,255]的数字。很好！你现在可以用计算机表示一张漂亮的黑白图片了！

从黑白图片到彩色图片，大家很自然的会想到什么？
没错！三原色！

# 什么是颜色？
当我们有了三原色后，怎么把颜色混合起来呢？
有两种方式：相减混色（subtractive mixture，图2 A）和相加混色（additive mixture，图2 B）。
![](</images/graphics-tutorials/茶余饭后图形学01 如何写出你自己的画图软件-2.webp>)
（图2. 来源：课程PPT by Prof. Daniel Ritchie, Brown University, 
CSCI 1230: Computer Graphics, Fall 2025）

像画画的颜料那种越叠越深的就是相减混色，而相加混色是把光投射到同一个点上，光越多越亮（见图2 B）。我们的各种电子屏幕都是相加混色。自然届的光也是相加混色。我们在后面讲phong光照模型的时候，也是把各种光照的贡献加起来，是相加混色。

因为图形学的各种效果目前是展示在屏幕上的，所以我们用的是相加混色的色光三原色Red, Green, Blue（RGB）。写过html的人可能知道，除了用rgb(255, 0, 0)外，还经常使用#FF0000，这就是把RGB的三种颜色从[0,255]改成了十六进制的表示方式。

关于颜色还有许许多多有趣的话题，比如这个许久之前的热议话题：白金or蓝黑？
![](</images/graphics-tutorials/茶余饭后图形学01 如何写出你自己的画图软件-1.webp>)
(图3. 来源：https://xkcd.com/1492/)

因为图形学除了模拟物理世界之外，我们的大脑如何解释物理世界也需要考虑在内。（“The human visual system is part of the graphics pipeline!”）除了RGB之外还有一些其他的颜色体系，可以更轻松的表达出一些在RGB体系中不方便表达的东西（想想直角坐标系和球坐标系！），这里就不详细展开了。

现在我们知道了，在每个像素点，用三个[0,255]的数字的分别表示红色、绿色和蓝色，合起来就能得到一张彩色图片。
![](</images/graphics-tutorials/茶余饭后图形学01 如何写出你自己的画图软件-3.webp>)
（图4. 来源：课程PPT by Prof. Daniel Ritchie, Brown University,

很容易想到，因为图片是方形的，所以我们用一个二维数组来表示整张图片，数组中的每个元素就代表一个像素。哈哈现在问题又来了（没错就是这么麻烦 = =），一个像素有RGB3个channel，我们是应该每个channel一个二维数组，还是应该用一个结构体表示同一个像素点的RGB三个值呢？

这个问题称为 SoA vs AoS
![](</images/graphics-tutorials/茶余饭后图形学01 如何写出你自己的画图软件-4.webp>)
（图5. 来源：课程PPT by Prof. Daniel Ritchie, Brown University, 
CSCI 1230: Computer Graphics, Fall 2025）

大家觉得应该怎么选呢？要考虑什么呢？

学过计算机体系结构的朋友们会想到一个东西叫缓存局部性（cache locality）。在写画图软件这个例子里，我们通常是对像素点的整体颜色进行操作，而不是对很多像素点的red channel进行操作，所以选用AoS。在整个图形学中都是AoS更常见，但后面如果我们讲如何加速渲染过程如果讲到SIMD（Single instruction, multiple data）的话（大概率不会...曾经脑子一热尝试实现SIMD差点疯掉（bushi），因为我们要一次操作多个同类数据，所以需要把AoS转成SoA进行计算。

# 开始写代码吧！
Ok讲了这么多我们终于开始看代码了！在茶余饭后，我们不看具体的代码实现，只讨论高屋建瓴的代码设计😎。

经过前面的讨论，我们需要在每个像素点，用三个[0,255]的数字分别表示RGB channels。听起来我们应该理所应当地选择int类型来存储这个数字？
有什么不对吗？
没错，这个[0,255]的数字只需要8 bit(1 byte)，而一个int类型有4 bytes。很巧的是，c++里有一个叫uint8_t的类型，大小刚好是8 bit(1 byte)!所以我们选用uint8_t来存储数据。
这里有一个trick，CPU的寄存器宽度>=4bytes，所以在做运算的时候会被隐式提升为int，算完再cast回uint8_t。

虽然在上一节颜色的讨论中我们只讲了RGB这三个channel，但在实际应用中通常使用RGBA颜色模型，第四个channel是alpha，代表这个像素的不透明程度（255为完全不透明），也就是颜色混合时这个像素占多大比重。这样做有个好处是内存通常用4bytes对齐（alignment），这对于内存访问和cache更加友好。

在图形学中其实我们通常不用int类型来处理颜色，通常用float。float值是连续的，方便进行各种乘法运算。

所以我们可以写一个RGBA类，里面有四个uint8_t类型的值r, g, b, a。可以运用重载运算符来简化颜色之间的运算，不然的话所有运算都需要对四个channel分别写。
```cpp
RGBA operator+(const RGBA &anotherColor) {
	RGBA color;
	color.r = std::min(255, this->r + anotherColor.r);
	color.g = std::min(255, this->g + anotherColor.g);
	color.b = std::min(255, this->b + anotherColor.b);
	return color;
}
```


接下来考虑一下图片的坐标系。我们的图片是2维的，但存储像素数据一般是1维容器。这和硬件有关，连续内存便于编译器优化，各种图形API也都用1维容器。在这个项目中我们可以使用`vector<RGBA>`（前面讲过的AoS）。同时写一个函数从图片的位置(x, y)转换到1维容器中的下标，来访问像素数据。

用过各种画图工具的大家应该都知道，如果你不拖动，只是点一下的话，一般来说出现的是一个圆，拖动时就是一个个圆的叠加。你可以改变笔刷的样式和颜色，但都是基于最开始的这个圆来改变的。所以我们要做的就是在鼠标经过（点击或拖动）的那个像素点为中心，画出这个圆。根据笔刷的大小来计算圆的半径，根据笔刷的种类来确定从圆心到边缘的颜色是如何变化的（比如图6中的线性笔刷）。
